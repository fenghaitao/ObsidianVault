## Definition
Code review amplification is the structural imbalance created by AI coding agents: every engineer now has vastly more code-producing power than code-reviewing power. This leads to piling pull requests, rubber-stamped reviews, and an expanding pool of code contributors (including non-engineers) whose work must be reviewed by the same engineering team.

## Key Information
- Identified by Armin Ronacher and Cristina Poncela Cubeiro as a scaling problem in AI-assisted teams
- Previously, teams were "supply constrained by creation of code" — the balance between writing and reviewing was naturally decent
- Now every engineer has a "multitude of producing power compared to their reviewing power"
- The total number of entities (humans + machines) participating in code creation outnumbers those who can carry responsibility — machines cannot be responsible for code changes
- Non-engineers (marketing, former CEOs) are now shipping code, but responsibility still rests with engineering
- Leads to more code reviews being skipped or rubber-stamped
- The goal of small PRs becomes harder to achieve as agents produce large, daunting pull requests (5,000+ lines)
- This is when engineers should be thinking most critically, but it's exactly when they're most overwhelmed and likely to tap out
