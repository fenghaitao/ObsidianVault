## Definition
"Code is not cheap" is Matt Pocock's counter-argument to the "code is cheap" premise of the specs-to-code movement. He argues that bad code is the most expensive it's ever been because it prevents developers from taking advantage of AI's full potential — AI performs well in good codebases but poorly in bad ones.

## Key Information
- Articulated by Matt Pocock in response to the "code is cheap" mantra of the specs-to-code movement
- Core argument: if you have a codebase that's hard to change, you can't take all the bounty that AI can offer
- AI in a good codebase actually does really, really well
- Bad code is more expensive than ever because it blocks AI productivity gains
- Good codebases matter more than ever, which means software fundamentals matter more than ever
- Contrasts with the "Code is Free" paradigm from Ryan Lopopolo — both agree code is abundant, but Pocock emphasizes that code quality determines whether AI can be effective
- The cost of bad code is not in producing it but in the opportunity cost of what AI cannot do with it
