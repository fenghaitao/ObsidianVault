## Definition

"Running code beats perfect code" is Joakim Recht's engineering principle: ship working code early to get feedback rather than polishing until every edge case is handled, because feedback is what drives correctness and growth.

## Key Information

- "Running code will always beat perfect code or beautiful code" (in the big picture, despite edge-case counterexamples)
- Saving commits until the implementation is "perfect" means working a month before getting feedback — you might be on a completely wrong track
- Tied to his other philosophy: "a software engineer needs to write code" — write code daily, without overthinking the "level" of code
