## Definition
Context as Code is the paradigm shift proposed by Patrick Debois where context (prompts, skills, instructions, documentation) becomes the primary artifact of software development, and code becomes a generated output. Just as Infrastructure as Code applied software engineering practices to infrastructure, Context as Code applies software engineering practices to context management.

## Key Information
- Introduced by Patrick Debois at the AI Engineer conference
- Core observation: developers increasingly tell AI what to do rather than writing code directly — context is what's being authored, code is what's being generated
- Code is also transforming back into context: large pieces of code are being turned into skills (reusable workflows) that solve more problems than hardcoded logic
- Parallel to the DevOps movement: "In 2009, I asked what if ops looked more like dev? Now I ask: what if context is the code?"
- Implies treating context with the same engineering discipline as code: versioning, testing, packaging, CI/CD, security scanning
- The LLM is the engine; context is the fuel — you can't change the LLM, but you can optimize your context
