## Definition
Agent as Knowledge Manager is the role transformation at the heart of Demand-Driven Context: the agent transitions from being a passive consumer of knowledge to an active manager of the entire knowledge lifecycle — discovering gaps, requesting information from domain experts, curating new knowledge, and organizing it for reuse by itself and other agents.

## Key Information
- **Role Shift**: In the push model, agents consume knowledge provided by humans. In the pull model, agents manage knowledge — they don't just consume, they discover, request, curate, and organize.
- **Lifecycle Management**: The agent handles: (1) Gap discovery — identifying what's missing from the knowledge base. (2) Demand extraction — producing a checklist of needed information. (3) Curation — documenting new knowledge in structured context blocks. (4) Organization — maintaining the knowledge base structure.
- **Human Role Change**: Humans shift from knowledge managers (writing documentation, building MCP servers) to domain experts who answer specific questions surfaced by agent failures.
- **Value**: "I don't want to be the knowledge manager of it. Let it do it." — Raj. This frees humans from the exhausting work of hand-writing domain context.
- **Multi-Agent Collaboration**: When multiple agents contribute to the same knowledge base (e.g., a GitHub repo), the agent-as-manager role includes conflict resolution via PR processes.
- **Gradual Improvement**: Each cycle of problem → failure → curation improves the knowledge base. After ~14 cycles, confidence can improve from 1.5 to 4.4.
