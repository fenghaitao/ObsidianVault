## Definition

Restraint is the product strategy discipline of choosing focus over capability — saying no to building features even when AI makes them trivially easy to build. It's the skill Brian Casel argues AI cannot replace, because it requires strategic judgment about what a product should be, not technical assessment of what can be built.

## Key Information

- The old bottleneck was execution (can't build fast enough); the new bottleneck is judgment (should we build this?).
- Restraint means: "We could build this, but it doesn't belong here."
- For products: saying no to feature requests that would dilute product identity, even if they'd land enterprise deals.
- For internal tools: purpose-built tools connected by agent skills beat monolithic apps — agents work better with focused systems.
- Practiced during the pre-planning "shaping phase" — before any spec or PRD is written.
- Brian's framework: start in Claude (not Claude Code), brain dump the idea and customer context, ask Claude to be a "strategic thought partner, not a yes-man" — challenge assumptions, surface trade-offs, spot scope creep.
- Output artifacts: problem statement, scope boundaries (in/out), key decisions with trade-offs, core user flows.
- In team settings: each person runs the exercise independently, then compare notes to find convergence/divergence.
