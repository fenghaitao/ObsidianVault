## Definition

Loop engineering is setting up a system that prompts Claude — rather than prompting Claude directly — so that parts of your workflow become recurring, autonomous loops.

## Key Information

- Thariq's definition: "instead of prompting Claude directly, you're setting up a system that prompts Claude."
- It comes naturally with Claude Tag: asking "every day do this thing" turns a one-off prompt into a running loop.
- Scaling to many loops (triaging feedback, implementing, monitoring, proposing improvements) requires real investment in good skills, good verification, and the right data sources so changes can land safely.
- Value claim: loops let teams monitor issues they "could just never have kept on top of before," increasing software-development velocity.
- A loop that runs autonomously like a software-engineering job is like hiring someone — you must ensure the work you hand it is actually valuable.
- Cost caveat: people more often run into *scope* problems than compute problems — starting a small mid-scope task (e.g., "refactor this function") and iterating, versus stepping up a level, stating the goal, exploring, then letting it run.
- Not to be confused with the career/management concept of [[Magic Loop]] (Ethan Evans).
