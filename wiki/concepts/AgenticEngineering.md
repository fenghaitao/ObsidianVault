## Definition
Agentic engineering is the paradigm of working with AI as a collaborator rather than merely using it as a tool. It represents the shift from treating AI as fancy auto-complete to treating it as an engineering partner — one that requires deliberate direction, context curation, and structured workflows to be effective.

## Key Information
- Coined/popularized by Brendan O'Leary of Kilo Code
- Core distinction: "using AI" (auto-completing through the day) vs. "working with AI" (directing work, knowing what to hand off and what to keep)
- 90% of engineers have used AI tools, but most cannot articulate their actual workflow with AI
- Built on the mental model of AI as an "energetic, enthusiastic, extremely well-read, often confidently wrong junior developer"
- Requires a mental model shift: AI agents are still tools, but must be thought about differently — more like managing a junior engineer
- Key skills: context engineering, structured workflows (research-plan-implement), session management, agent configuration
- Armin Ronacher's framing: "We're no longer just using machines. We're now working with them."
- Dex Horthy's principle: "AI can't replace thinking. It can only amplify the thinking you've done or the lack of thinking you haven't done."
- Practical habits: one task per session, watch the context meter, start fresh when things go off the rails, use AI to summarize for new sessions
