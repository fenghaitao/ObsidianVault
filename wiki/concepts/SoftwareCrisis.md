## Definition
A recurring historical pattern in software engineering where the demand for software and the complexity of systems outpace the ability of engineers to manage them. Each generation has faced its own software crisis, resolved by new tools and methodologies that then enable the next crisis at a larger scale.

## Key Information
- First observed by Edsger Dijkstra and others in the late 1960s/early 1970s: demand for software exceeded ability to deliver
- Each generation's crisis was met with new tools: C (1970s), personal computers (1980s), OOP (1990s), Agile (2000s), Cloud/DevOps (2010s)
- Today's crisis is driven by AI code generation, which Jake Nations calls the "Infinite Software Crisis"
- The pattern: each solution makes the mechanics easier but does not address the fundamental difficulty of understanding what to build
- Dijkstra's generation responded by creating the discipline of software engineering itself
- The current crisis requires a similar discipline: not outsourcing thinking to AI, but using it to accelerate mechanical parts while maintaining human understanding
