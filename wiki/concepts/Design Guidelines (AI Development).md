## Definition

Design Guidelines is the third PRD in Lazar's AI development documentation framework. It defines how the app should look and feel, including CSS elements, because AI is "sometimes over creative" and needs concrete design steering.

## Key Information

- Third document in the PRD framework after Implementation Plan
- Defines how the app should look and feel: "I need to define how I want the app to look and feel because I'm still working with a system that is not emotionally intelligent yet."
- Includes CSS elements for concrete design direction: "I like to see some elements of CSS in design guidelines because AI is sometimes over creative."
- This is where Lazar does "a little bit more technical steering" — design is trickier than code for AI
- Fonts are a major focus: "People don't talk about fonts at all that work with AI. They're like 60% in my mind, maybe even more in how your output's going to look."
- Learning design styles (Bauhaus, glass morphism) and how to prompt for them is a key skill
- Lazar built an app (UI style.lovable.app) with 18 different design styles and prompts to replicate them
