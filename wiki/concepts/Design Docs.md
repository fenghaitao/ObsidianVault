## Definition

Design Docs are written documents that explore the pros and cons of different technical approaches before implementation begins. They are a critical part of the engineering workflow, used to get feedback, align stakeholders, and demonstrate technical depth.

## Key Information

- Ricky's Google internship project was unusual: he wrote only 800 lines of code but produced a "really complex design doc that explored a lot of pros and cons of different approaches"
- The design doc was how Ricky was able to show his productivity and technical depth despite low code output — it demonstrated he could find a solution to a complex problem
- Writing a design doc before coding is standard practice: you write it, get feedback, and then implement
- Design docs are part of the "writing around the code" that Ryan described as essential to the engineering job
