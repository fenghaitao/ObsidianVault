## Definition
Agent-First Software Development is the principle that everything an engineer can do, the AI agent must also be able to do. It encompasses not just code production but debugging, testing, planning, and all technical work. The engineer's role shifts from doing the work to driving the agent and moving higher up the value chain.

## Key Information
- Core principle: "everything that you can do, the agent must be able to do"
- Encompasses all technical work, not just code production: debugging, testing, planning, and more
- The engineer's job moves up the stack — analogous to the transition from Unix sysadmin to SRE when cloud arrived
- Analogy: sysadmins used to rack servers and cable things; cloud came and they moved to automation-oriented SRE work that was more impactful and higher paid
- This transition is happening 100x faster than the sysadmin-to-SRE shift
- Engineers should be driving agents less and less, moving higher up the food chain
- The agent delivers real value — code, products, to customers
- Even if models and harnesses don't improve (which they will), the building blocks exist today to move vast amounts of work to agent-first
- Can feel weird initially, especially when connecting agents to production systems
- Not reckless: mature companies have controls, permissions, and audits that give confidence to unleash agents like engineers
- Claude Code used across Intercom outside of software engineering — gone "completely viral"
- Brian Scanlan's example: during a security incident, Claude Code automatically downloaded files, did full analysis, concluded it was innocuous, and told him next steps — all by understanding the problem intent and invoking the right internal skill
