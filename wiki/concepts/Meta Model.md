## Definition
A Meta Model is a structured map of how a domain is organized, showing relationships between business processes, systems, APIs, and business/tech jargon. In the Demand-Driven Context methodology, it serves as a navigation map that helps agents understand how to traverse the knowledge base.

## Key Information
- **Structure**: Business processes → Systems → APIs → Business/tech jargon, with relationships linking them.
- **Navigation Function**: Without a meta model, agents are "dumping files" with no way to navigate — they don't know which files are relevant to a given task. The meta model tells them: "if you change this system, these business processes are affected and these APIs need to change."
- **Optional but Recommended**: The meta model is not necessary for the Demand-Driven Context approach to work, but it's a strong add-on that produces more value.
- **File Structure as Meta Model**: In a GitHub-based knowledge base, the file structure itself can serve as a representation of the meta model, giving agents a natural navigation path.
- **Relationship to Context Blocks**: Context blocks are organized according to the meta model, creating a coherent structure rather than a flat dump of files.
