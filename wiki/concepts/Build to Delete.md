## Definition

Build to Delete is the principle that software in the agent era is disposable — we will rebuild the same things many times with better models and better agents. It represents a mindset shift from building permanent systems to accepting that today's implementation will be replaced as the underlying AI capabilities improve.

## Key Information

- **Articulated by Philipp Schmid** as the final core principle for building agents
- **The bitter lesson**: Everyone in AI is learning that software is disposable. Things will change. Better models will arrive. Better agent architectures will emerge
- **Contrast with traditional engineering**: Traditional software engineering values long-lived, maintainable systems. Agent engineering acknowledges that the current implementation is temporary
- **Implication for investment**: Don't over-invest in perfecting today's agent implementation. The model improvements alone may render your optimizations obsolete
- **Iterative rebuilding**: Each generation of models enables cleaner, simpler implementations. What took complex prompt engineering and tool design with one model may be handled natively by the next
- **Mindset shift**: Build solid systems, but hold them loosely. Be ready to throw away and rebuild when the underlying capabilities improve significantly
- **Not nihilism**: This doesn't mean don't build anything — it means build pragmatically, knowing the landscape will shift
