## Definition

Lazar (Lazar Yavanovich) is the first official "vibe coding engineer" at Lovable, hired full-time to build internal and external products using AI tools. He has no traditional coding background — he never wrote a single line of code in his life — yet builds production-grade software across all departments. He represents a new AI-era career path.

## Key Information

- First official "vibe coding engineer" at Lovable; title is literally "vibe coding engineer"
- Hired by Elena Verna onto the growth team; now works across all departments (growth, GTM, enterprise, community)
- Non-technical background: never wrote code; was a forestry engineer by trade; had diverse career including blue collar jobs, waiting tables, community management, social media
- Joined Lovable after building in public on LinkedIn and YouTube, sharing his vibe coding projects and knowledge
- Spends 80% of time in planning/chatting, only 20% in executing — optimizing for the right kind of speed

## Key Frameworks & Advice

### Parallel Prototyping
Start 4-5 projects simultaneously: (1) brain dump via voice, (2) typed thoughtful prompt, (3) mock design from Mobin/Dribbble, (4) code templates from 21st Dev/Build UI. This clarifies the idea and saves tokens.

### PRD Documentation
Four documents: Master Plan, Implementation Plan, Design Guidelines, User Journeys. All feed into tasks.md. Use rules.md/agent.md for perpetual context.

### 4x4 Debugging Framework
(1) Use tool's "try to fix," (2) Add console logs for awareness, (3) Use external tool (Codex, Claude) as consultant, (4) Revert and re-prompt. Then ask: "How can I prompt you better next time?"

### Genie/Aladdin Metaphor
AI has limited token context window (like 3 wishes). Vague requests = wrong results. Be specific, provide references, give context.
