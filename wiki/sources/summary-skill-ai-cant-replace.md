## Core Summary

Brian Casel argues that "restraint" — the discipline to say no to building features even when you can — is the skill AI cannot replace. As AI makes building trivially easy, the bottleneck shifts from execution to judgment: should we build this at all? He provides a framework for the pre-planning "shaping phase" where strategic decisions happen before any spec is written, and demonstrates how plan mode has become a first-class feature across Claude Code, Cursor, and Codex.

## Key Points

- The old bottleneck was execution (can't build fast enough); the new bottleneck is judgment (should we build this?).
- Restraint = choosing focus over capability. The discipline to say "we could build this, but it doesn't belong here."
- Example: a client portal product tempted to add invoicing for enterprise deals — doing so dilutes the product identity and attracts the wrong customers.
- For internal tools: purpose-built tools connected by agent skills beat monolithic apps. Agents work better with focused systems.
- Pre-planning framework: start in Claude (not Claude Code) with a strategic conversation. Brain dump the idea, customer feedback, context. Ask Claude to be a "strategic thought partner, not a yes-man" — challenge assumptions, surface trade-offs, spot scope creep.
- Output artifacts: problem statement, scope boundaries (in/out), key decisions with trade-offs, core user flows.
- Plan mode is now a first-class feature in Claude Code, Cursor, and Codex — all use shift+tab, all ask clarifying questions.
- Claude Code now auto-enters plan mode for substantial prompts (no manual shift+tab needed).
- NimbleList (sponsor): visual workspace for planning with markdown, mockups, diagrams, and agent sessions in one place.
