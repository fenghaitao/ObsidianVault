## Core Summary

Brian Casel shares three ideas from an Anthropic team member's article about using Claude Code in Slack internally: (1) feature ideas start as working PRs against the production codebase, not mockups; (2) anyone in the organization can ask Claude technical questions about the codebase directly in Slack; (3) Claude can combine codebase knowledge with analytics/event data to answer business questions. The common thread: the codebase becomes a shared organizational resource, not something locked in engineering terminals.

## Key Points

- Idea 1: "I don't send memos or make mockups anymore. I just make Claude Code prototypes." — feature ideas start as real PRs using real components and patterns.
- Idea 2: Support, marketing, and sales can ask Claude technical questions directly in Slack — no engineering bottleneck for answers about edge cases, ship dates, or feature rationale.
- Idea 3: Connect Claude to analytics/event stores — questions like "what's the completion rate on the new onboarding flow?" get answered by combining code knowledge with data.
- The codebase becomes a shared intelligence resource powering the entire team, not just engineering.
- Engineers stay focused on building instead of context-switching to answer questions.
