## Core Summary

Harvard's David J. Malan explains why CS50 still starts with C in 2026: C sits "about as close as you can get to the hardware" before assembly code while retaining English-like syntax, and its small standard library forces students to build data structures themselves and reason from first principles. He pushes back on the clickbait claim that CS50 teaches things engineers "don't need to know": the better framing is that full-stack engineers "won't need to use" C, but they absolutely need the underlying knowledge. That knowledge scaffolds higher-level languages (the week-5 hash table becomes a one-line Python dict in week 6) and is what separates an "engineer" from a mere "coder."

## Key Points

- Why start with C: it is the closest language to the hardware before things "devolve into assembly code" (and, beyond that, "zeros and ones"), yet it keeps "English-like syntax and abstractions on top of lower-level primitives."
- C pedagogically balances exploring procedural programming (loops, conditions, functions, variables, return values) with being "a pretty small language" with a small standard library — so most things must be built yourself.
- CS50 leverages this: by week 5 students build their own hash tables and study singly/doubly linked lists, tries, trees, and abstract data types (stacks, queues); week 6 "whittles" that down to a one-line Python dictionary.
- Unlike Java or C++ (with the STL and other libraries), C makes you build — not instantiate — data structures, which Malan calls a good educational exercise.
- Three payoffs of building from the bottom up: make more-informed data-structure design decisions; diagnose problems by first-principles reasoning about data storage and algorithms; and scaffold higher-level languages.
- On the "you don't need to know how the computer works" mindset: it is "absolutely the wrong mindset" for a full-stack engineer, who by definition should understand all the layers; the correct formulation is that you "won't need to use these things," not that you don't need to know them.
- C remains ranked #1/#2 annually due to high performance; Malan personally uses C only ~5 weeks a year and Scratch ~1 week, but the extracted principles remain valuable.
- CS50's goal is "not to output programmers, but engineers and educated citizens" who understand technology from first principles — the engineer-vs-coder distinction.
