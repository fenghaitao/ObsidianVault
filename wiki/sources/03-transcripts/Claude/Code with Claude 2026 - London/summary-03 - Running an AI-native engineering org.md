## Core Summary

Fiona Fung, engineering lead for Claude Code and Cowork, shares lessons from running an AI-native engineering org. The core insight: bottlenecks have moved. When coding is no longer the bottleneck, upstream and downstream processes must change. Old norms that quietly stopped working include planning (code wins debates, not whiteboarding), code review (agent-on-agent review), onboarding, hiring, and org shape. New bottlenecks are verification, review bandwidth, and maintenance at higher throughput. Key practices: prototype to learn, then scale to production; every manager starts as an IC; test-driven development becomes enjoyable with Claude.

## Key Points

- **Bottlenecks shifted:** coding, writing tests, and refactoring are no longer slow. New bottlenecks: verification, code review bandwidth, maintenance at scale.
- **Old processes that quietly stopped working:** planning norms (build is cheap, arguing is expensive), code ownership (all commits co-authored by Claude), code review, team makeup, knowledge sharing.
- **Technical debates:** code wins. Generate multiple PR versions instead of whiteboarding. Prototyping is now a great starting point since Claude can scale prototypes to production.
- **Test-driven development:** became enjoyable with Claude -- write the test, verify it fails, Claude fixes the bug, test already exists.
- **Onboarding:** changed significantly; Fiona onboarded by fixing bugs with Claude.
- **Org shape:** flatter orgs; every manager on Claude Code starts as an IC first.
- **Verification:** the biggest new bottleneck; agent-on-agent review (Claude Code Review product) is critical.
