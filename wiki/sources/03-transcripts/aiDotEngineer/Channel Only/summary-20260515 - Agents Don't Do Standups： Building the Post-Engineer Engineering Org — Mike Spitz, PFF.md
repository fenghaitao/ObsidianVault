## Core Summary
Mike Spitz presents a PFF case study where two engineers using AI coding agents (Claude Code) achieved 25x deployment frequency and 10x output versus a 10-engineer team, leading to the elimination of traditional Agile ceremonies (standups, sprint planning, retrospectives) in favor of a streamlined huddle-based, spec-driven, fully autonomous development pipeline.

## Key Points
- PFF is a sports data company (100M page views/year, 9M annual drafts) with ~200 employees and ~20 engineers, fully distributed across India, Spain, and the US.
- Two top engineers using AI agents deployed 5x/day vs. the 10-engineer team's 1 deploy every 5 days — a 25x difference (partially explained by smaller team size).
- Output measured via blended tickets + code complexity showed 10x improvement; customer satisfaction surveys averaged 8.6/10 (up from 7–7.5 before AI).
- The case study built features in under 2 months that were previously estimated at 4 months, with compounding gains as engineers unblock each other faster.
- Scrum and traditional ceremonies were eliminated: no project manager, no standups, no sprint planning, no sprint refinement, no formal retrospectives.
- Replacements: bi-daily 30–60 min "huddles" with engineers, product, and design for instant feedback; customer satisfaction surveys as the retrospective signal.
- Development flow: spec → agent interviews stakeholders → agent generates Lightweight Design Document (LDD) → LDD distributed for engineer feedback → auto-create tickets (structured to avoid blocking dependencies) → auto-create PRs.
- Agentic code review handles style/opinionated feedback (variable names, formatting), removing emotional friction so engineers focus on system design and big picture.
- Autonomous QA: merged PRs auto-deploy to staging → QA agent checks tickets against acceptance criteria → flags failures. Future goal: agent auto-creates fix PRs for failed criteria (self-healing).
- Engineering culture and patterns should be encoded in composable skills (e.g., service repository pattern for APIs, feature flag generation for trunk-based development).
- Adoption strategy: start with your best engineers, go slow with a phased approach, experiment in non-critical systems first, then scale.
- The type of engineer who thrives: curious, self-directed problem-solvers. Engineers needing highly prescriptive specs will struggle.
- Small companies have an adoption advantage over large enterprises; the compounding effect means delays compound rapidly.
- Token expenditure estimation may replace ticket estimation once API subsidy ends.
- Security, product feel/brand consistency, and scale/complexity control remain human responsibilities, primarily enforced through the LDD.
